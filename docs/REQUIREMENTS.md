# 剑三画面监控需求基线 v0.20

更新：2026-11-05。下一轮以此文档及 HANDOFF.md 为准。

## 已实现并需保留

- 两个启动入口：PVP 监控自身/目标 Buff；PVE 监控技能栏状态及 CD。
- 数据库按技能名、图标、门派及心法选择；支持编辑心法预设、默认基础 CD、顺序。共用门派技能按适用心法纳入，不能一律删除。
- 多个可命名监控栏，共用各自框选区域，默认白云/小剑/斧头；列表按门派、技能合并配置，技能可上下移动。
- 左至右框选三个目标心法，自动加载三名目标的预设；目标变化或丢失时隔离旧状态，同心法的不同目标独立计时。
- 透明无边框浮窗，图标紧贴、完整显示，无滚动条，可拖动/缩放/穿透，再点主按钮关闭；目标分云/剑/斧三行。
- 浮窗跟随列表合并顺序。默认匹配阈值 85%，Buff 连续确认出现后启动 CD，恢复前 N 秒声音提醒。
- 充能可开启，默认两层满充能，可设置 1–9 层；逐层回充，第二次使用不重置首层 CD。中央显示下一层 CD，右下角显示剩余层数。
- 同栏同技能的手动/自动配置共享充能开关及上限；各目标剩余层数与队列独立。
- 保存及导入/导出包含监控框、目标框、图标、预设、顺序、性能和浮窗设置。重启尝试绑定来源进程，不要求每次框选。
- 主界面不恢复“从画面录入图标、导入 PNG、测试画面、测试声音”四个已移除入口。

## 当前实现边界

- YOLO11n ONNX：32 心法类别及通用图标类；Buff/技能身份仍由候选框内模板复核，不是全技能 YOLO 分类。
- 长条 ROI 重叠分块；心法类别和库图双重复核后可排除其他技能。相关性分数不等于正确概率。
- 默认检测 8 Hz、预览 2 Hz、CPU 两线程、静态复用关闭；可选复用最长一秒，目标标记始终重新检测。
- CD/充能是画面估算。PVP 依靠 Buff 出现边沿，连续施放无可见变化时无法保证识别；PVE 支持右下角数字，但字体、遮挡和缩放覆盖有限。
- 游戏插件 .jx3dat 尚未解码，不能宣称直接导入监控；Pakv4 已提取部分资源与基础调息数据，未确认值保持未知。

## 下一轮优先级与验收

1. P0 端到端充能：真实自动目标配置连续使用两次，角标 2→1→0、首层 CD 不重置、逐层恢复；不能只测手动配置。
2. P0 识别及状态稳定性：独立录制有/无 Buff、文字遮挡、复杂背景、目标切换和静态画面样本。分别统计定位召回、误触发、漏触发及状态丢失；不靠任意压分通过测试。
3. P1 负载：真实多栏多技能记录采集/识别 Hz、批耗时、CPU/GPU；降低重复工作但不牺牲目标信任更新及计时。
4. P1 配置与界面：跨重启、导入、分辨率/DPI变化验证区域恢复；高 DPI 编辑窗口布局；同技能合并与目标隔离一致。
5. P1 工程化：自包含测试素材、去除测试对个人临时目录的依赖；干净环境构建和发布；将生产代码与自检逐步拆开。

每次优化以可复现问题为入口，先建立失败用例，再修复、验证并记录实战限制。禁止以自检数量替代真实准确率。
